> 或 [README.en.md](../README.en.md)（English）。
>
> 本文档内容与仓库状态同步维护，随代码一起演进。

把一个 HTML 文档解析成幻灯片，在可视化工作台里直接改版式与文字，再导出成**真正可编辑的
`.pptx`**。单文件、纯离线、零依赖。

```
双击打开 WizDeck.html  →  拖入 HTML  →  编辑  →  导出 PPTX
```

---

## 它解决什么问题

老师手上的课件通常是 AI 生成的一份 1920×1080 的 HTML。这份 HTML 好看，但**改不动**：
改一个字要翻源码，挪一个卡片要对像素，最后还得想办法变成 PPT。

WizDeck 把这条链路打通：

| 环节 | 做的事 |
| --- | --- |
| 解析 | 自动识别分页结构，把每一页还原成 1920×1080 的独立画布，版式 1:1 保留 |
| 编辑 | 拖动、缩放、旋转、双击改字、改色、改字号、对齐分布、图层、组合、撤销重做 |
| 导出 | 浏览器内直接生成 PPTX（OOXML + ZIP 自己打包），文字是**真文本框**，不是图片 |

---

## 快速开始

1. 双击 `WizDeck.html`（Chrome / Edge / Firefox 均可，不需要服务器、不联网）。
2. 点空状态的「打开 HTML 文件」选择文件，或把 `.html` 直接拖进窗口（之后可随时 `Ctrl+O` 换文件）。
3. 左侧栏切页／拖拽排序；画布上点选元素；右侧栏改属性；双击文字直接改。
4. 点右上角「**保存与导出** ▼」，在展开的菜单里选「导出 PPTX」，浏览器下载 `.pptx`。

## 导出的 PPTX 里，什么是「可编辑」的

分层策略按「正确性优先，可编辑性其次」决定：

| 画面内容 | 导出成 | 可否在 PPT 里继续编辑 |
| --- | --- | --- |
| 文字 | 真文本框（**逐视觉行**定位，断行与浏览器一致） | ✅ 改字、字号、颜色、字体 |
| 纯色块 / 边框 / 圆角矩形 | 真形状（`p:sp`） | ✅ 改填充、轮廓、圆角 |
| 图片（data URI） | 真图片对象（`p:pic`） | ✅ 替换图片 |
| 渐变 / 外阴影 / 滤镜 / 旋转 / SVG / 半透明 | 浏览器渲染后作为 PNG 贴图 | ⚠️ 视觉 100% 一致，但这一层不可再改文字 |
| 被贴图元素压住的文字 | 一起烘进贴图 | ⚠️ 同上（优先保证不遮挡） |
| 页面底色 | 铺满画布的矩形形状 | ✅ 直接改背景色 |
| 演讲备注 | 写入 PPTX 备注页 | ✅ |

一个 6 页示例的实测结果：**167 个形状，其中 97 个是可编辑文本框**。

## 分页识别规则

引擎按下面的顺序判定怎么切页，命中即停：

1. `data-wd-slide` 显式标记 —— 最高优先级
2. reveal.js / impress.js 约定（`.slides` / `.step` / `.impress` / `data-reveal`）
3. 语义与类名提示（`<section>`、`.slide`、`.page` …）**并用几何一致性打分**
   （宽度高度是否一致、长宽比是否接近 16:9、每页是否够大）
4. 全幅绝对定位区块（AI 生成课件的常见写法）
5. 统一几何检定的任意候选集合
6. 唯一外层容器 → 往里再找一层
7. 兜底：整篇当 1 页（界面会提示置信度低）

想让分页 100% 确定，用第一种：

```html
<section class="slide"> … </section>
<!-- 或 -->
<div data-wd-slide> … </div>
<!-- 或 -->
<div class="slides"><section>…</section><section>…</section></div>
```

写 HTML 时的建议：**页面 1920×1080、用绝对定位、用系统字体**，还原度最高。

## 工作台设计语言

编辑器外壳参考 bento 的克制风格：浅灰金属质感面板 + 白纸舞台 + 琥珀强调色。

- 顶栏：**扁平无边框**的图标 + 文字按钮（新建页 / 文本框 ▾ / 标题 ▾ / 形状 ▾ / 表格 /
  公式 ▾ / 图表 ▾ / 图片 / 视频 / 格式刷 / 查找 / 保存与导出 / 放映 / 主题 / 帮助），
  撤销重做按约定保持 `↶ ↷` 纯符号；
  右侧的文件名胶囊同时兼任「未保存」提示 —— 有改动时它前面亮起一个琥珀点（原先顶栏左侧那个
  独立的「有未保存修改」徽章已撤掉，文稿名和「它是不是最新」本来就是同一件事）；
  另有随选区出现的文字格式条（B I U · A− A+ · 对齐 · 文字色）。
  宽度不够时（1280–1600px 的笔记本 + 选中文字）顶栏可**横向滚动**，滚动条隐藏。
- 左栏：幻灯片轨（实时缩略图、拖拽排序、页内操作）
- 中栏：舞台（点阵背景、选择框、八向缩放手柄、旋转手柄、浮动工具条）
- 底栏：页码、画布尺寸、当前选中、**缩放**（`−` / 百分比 / `＋`，点百分比回 100%）
- 右栏：属性检查器（页面属性 / 元素属性 / 快捷色板 / 自定义 CSS / 图层）
- 另有：深色主题、放映模式、进度遮罩、提示条

改版的取舍：**功能不减，入口收敛**。原先散在右栏的「添加元素」全部收进顶栏插入组
（文本框 / 标题 / 形状 / 表格 / 公式 / 图表，各自带下拉；图片与视频因为要弹系统文件
选择器，是两个平级按钮而不是下拉项），
保存与导出合并成单个下拉，缩放从顶栏挪到底部，右栏不再承担插入职责 ——
高频操作在上、低频微调在下，右栏回到「改属性」的单一职责。

顶栏图标是**内联线性 SVG**（`build/shell.html` 顶部一份 `<symbol>` 图标集），
不是 emoji：emoji 走系统彩色字体，跟 12.5px 的中文标签并排时基线对不齐、字重也不一致。
图标描边 `currentColor`，深浅色主题自动跟随，不需要维护两套图。

## 实现要点（以及踩过的坑）

这些都是实测踩出来、已修掉的真实问题，记下来避免以后重犯：

1. **几何必须在真实布局里量。** `DOMParser` 生成的是无渲染上下文的文档，
   `getBoundingClientRect()` 全是 0。所以先挂进离屏 iframe 再测量、再切页。

2. **每页锚到自己的左上角。** 多页文档里第 2 页的自然流位置就是 `top: 1112px`，
   按「全局最小偏移」归一并不会把它搬回原点，整页会落在画布外变成空白。

3. **`display:none` 的页量出来是 0×0。** reveal / Bento 这类「一次只显示一页」的文档，
   未激活页被 CSS 收起，直接测量会得到零尺寸并烘焙成空页。
   解析时先临时恢复可见再测量、量完立刻还原；仍量不出的候选再单独装帧测量。

4. **ZIP 的存储条目（method 0）不能带 deflate 帧头。** 曾经把
   「deflate stored 块的 5 字节帧头 + 原始字节」当成载荷写进去，
   压缩大小与真实数据差 5 字节/块，整包 CRC 校验失败、PowerPoint 报文件损坏。
   method 0 的载荷就是原始字节本身。

5. **混合内容里的裸文本会丢。** 一个块里既有裸文本、又有块级子元素时
   （`<div class="formula">公式<small style="display:block">注解</small></div>`），
   浏览器把裸文本包成匿名块盒；只递归子元素会把公式整段丢掉。
   现在把裸文本单独收成一个文本框，再对块级子元素递归。

6. **`<a:bodyPr>` 少了 `>` 会让所有文本框消失。** 属性后来直接接了
   `<a:noAutofit/>`，生成出不良构 XML，渲染器把每个 `p:sp` 整块丢弃。
   导出前对每个 XML 部件做良构 + 标签配平自查就是这个教训的产物。

7. **新版 Chromium 不再把跨文档 iframe 交给 `drawImage`。**（抛
   `TypeError: The provided value is not of type (CSSImageValue or …)`）
   所以像素路径改为「计算样式内联 → 序列化进 SVG `<foreignObject>` → 当图片画到 canvas」。

8. **`cloneNode(false)` 不复制文本节点。** 克隆素样式时只搬元素会得到一副没有文字的骨架。

9. **离屏帧必须留在视口内且仍被绘制。** 移出视口或 `visibility:hidden` 会让浏览器跳过绘制，
   于是 canvas 捕获拿不到像素。用「完全透明 + 不接收事件」保持可绘制。

10. **`file://` 下 `blob:` iframe 会被当成跨源**（`contentDocument` 为 `null`），
    而 `srcdoc` 帧始终同源 —— 所以统一用 `srcdoc`。

11. **反复给同一个 iframe 赋 `srcdoc` 时，`load` 可能早于内容解析完成触发**，
    此时 `contentDocument` 还是空的 `about:blank`。必须校验内容真的落地再继续。

12. **OOXML 的颜色值不能带 `#`。** `<a:srgbClr val="#faf8f3"/>` 会被部分渲染器当成黑色，
    整页变黑；正确写法是 `val="faf8f3"`。

13. **`<p:bg>` 实色填充在部分渲染器上会整页变黑。** 页面底色改用铺满画布的矩形形状表达，
    兼容性更好，用户也更容易直接改。

14. **`.foo{display:flex}` 会盖掉浏览器默认的 `[hidden]{display:none}`。**
    浮层必须显式补一条 `[hidden]{display:none}`，否则「隐藏」的面板仍然铺在工作台上。

15. **允许换行的文本框要夹在画布内。** 为抵消字体度量差异给 10% 横向缓冲，
    但必须 `min(缓冲后宽度, 画布宽 - 起点x)`，否则右对齐的数字/页码会被推出可视区。

### 编辑交互的坑（这些才是「能看不能用」的根源）

16. **iframe 里的事件不会冒泡到父页。** 拖动从画布内部开始，但 `pointermove` /
    `pointerup` 只在帧文档里派发，父页 `window` 永远收不到 —— 拖动无法收尾，
    `E.drag` 一直挂着。父页大部分快捷键分支都以「不在拖动中」为前提，
    于是**拖动一次之后，微调、Delete、Ctrl+D、Shift 多选全部失灵**。
    现在把父页、iframe、帧内 document/window 都挂上监听，并把事件规范化成统一的点对象。

17. **键盘焦点会落进 iframe。** 点一下画布后 `document.activeElement` 变成 iframe，
    按键事件改在帧文档里派发，父页同样收不到 —— 快捷键「点一下就失效」。
    现在帧内 `keydown` 会转交给父页处理。

18. **判断「是否在输入框里打字」不能用 `ev.target`。**
    事件从帧里冒泡过来时 target 可能是 body，并不等于焦点元素。
    要用 `document.activeElement`，并且只对真正的文本输入框让路
    （复选框 / 颜色选择器不该吞掉 Delete 和方向键）。

19. **`style.setProperty('backgroundColor', …)` 是静默无效的。**
    setProperty 只认 CSS 属性名（`background-color`）。
    传错名字既不报错也不生效 —— 填充色 / 文字色 / 边框色全都「选了没反应」。
    所有设置样式的入口现在统一做 camelCase → 连字符归一。

20. **长写属性压不过简写属性。** 内联样式里已有 `background: rgb(...)` 时，
    再 `setProperty('background-color', …)` 完全无效。改颜色前必须先清掉简写，
    并用计算值把背景图 / 位置等其他子属性补回去。

21. **同一属性的两个输入框会互相回灌。** 程序化写 `input.value` 会**同步**派发
    `input` 事件，取色器会用它的旧值再调一次改样式，把刚改好的颜色覆盖回旧值。
    同步另一个控件时要挂起监听，并只在值真的变化时才写。

22. **命中测试要取「最内层」可选元素。** 画布本身通常是一个带背景色的容器，
    它自身也算「可选」，如果只判断「祖先里有可选元素」，
    那么任何点击都会命中最外层容器，永远选不到里面的卡片和标题。

23. **`caretPositionFromPoint` 会跨元素返回光标位置。** 它给的是整段文字里最近的
    插入点，可能落在与命中元素无关的兄弟节点上。只有确认它位于命中子树之内才能采信，
    否则会把点击目标劫持成另一个元素。

24. **撤销 / 重做 / 切页会重建 iframe 文档。** 旧选区引用变成游离节点，
    `getBoundingClientRect()` 全是 0 —— 选择框会缩成一点或直接消失。
    重建舞台后必须丢弃选区（`pruneSelection`）。

25. **选择手柄会跟着画布缩放。** 画布缩到 38% 时，10px 的手柄只剩不到 4px，根本点不中。
    用 `scale(1 / zoom)` 做反向缩放，让手柄在任何缩放级别都保持恒定屏幕尺寸；
    描边同理。

26. **`.overlay > * { pointer-events: auto }` 会盖掉新加的整屏浮层。**
    这条规则是给选择手柄用的，优先级与 `.guides` 相同但更靠后，
    于是对齐参考线那层浮层把指针事件全部吃掉 —— **画布完全点不动**，
    而且没有任何报错。整屏浮层要么放在 `.overlay` 之外，要么显式提高优先级。

27. **给父元素设 `pointer-events: none` 会连带改变子元素的默认行为。**
    进入框选时曾把 `.stage-canvas` 设成 `none`，结果整个舞台再也收不到鼠标事件
    （`getComputedStyle(.stage).pointerEvents` 也会跟着变成 `none`，很容易误判）。
    正确做法是让帧内把事件转发出来，而不是屏蔽事件。

28. **画布几乎被 iframe 盖满，空白处的事件落在帧里。**
    所以「点空白取消选择 / 拖动框选」必须由帧把起点换算成父页坐标后交给父页处理，
    父页自己监听 `stage-canvas` 是收不到的。

29. **`style.setProperty` 只认 CSS 属性名。** `background-color` 可以，`backgroundColor` 静默失败。
    所有设置样式的入口统一做 camelCase → 连字符归一（`toCssProp`）。

30. **长写压不过简写。** 内联已有 `background: rgb(...)` 时改 `background-color` 完全无效，
    必须先清简写并用计算值补回其它子属性。

31. **同一属性的两个输入框会互相回灌。** 程序化写 `input.value` 会同步派发 `input`，
    取色器会用旧值把颜色覆盖回去；同步时要挂起监听。

32. **命中测试要取「最内层」可选元素。** 画布本身是带背景色的容器、也算可选，
    只判断「祖先里有可选元素」会让任何点击都命中最外层。

33. **`caretPositionFromPoint` 会跨元素返回光标位置。** 只有确认它落在命中子树内才能采信。

34. **撤销 / 重做 / 切页会重建 iframe 文档**，旧选区引用变成游离节点，
    `getBoundingClientRect()` 全是 0，选择框会缩成一点或消失。重建后必须丢弃选区。

35. **`commit()` 会重建舞台文档。** 批量添加元素时，中途拿到的节点引用会失效
    （`style.width` 读出来是空）。要等一轮事件循环后重新查询。

36. **浮层没关掉会吃掉后续所有点击。** 模态与右键菜单都是整屏覆盖的，
    测试里点过「快捷键一览」之后如果不关，后面每个用例都会莫名失败。

### 工作台的坑（第三轮：定位与手感）

39. **展开按钮不能放在被折叠的元素里面。** 收起按钮原来在 `.panel-head` 里，
    而 `.panel-head` 在折叠时是 `display:none` —— 一收起按钮就跟着消失，
    再也点不回来。现在折叠后由**面板之外**的贴边拉手负责展开，
    顶栏还加了「显示 / 隐藏两侧面板」总开关。

40. **行内元素不能按块级元素那样定位。** `<em>`/`<span>` 这类行内标签，
    `getBoundingClientRect()` 返回的是**所有行盒片段的并集**；
    一旦设成 `position:absolute`，`left/top` 的参照会变成包含块原点 ——
    实测 `<em>` 被钉住后整体平移了父元素的偏移量 (96, 353)，看起来就是「文字跳位」。
    现在行内排版标签只在「自身有底色/边框」（看起来是个标签块）时才允许选中。

41. **整页底板不该参与点选。** `.slide` 通常铺满画布又有背景色，
    于是点在页面空白处会选中一个 1920×1080 的大盒子，感觉「点哪都选中一大块」。
    现在直接铺满画布的直接子元素被判为「整页底板」而不可点选 ——
    页面底色交给右侧「幻灯片属性 → 背景」修改。

42. **固定宽度是文字平移的元凶。** 元素宽度来自 `auto` 时，钉住后**不要**写死宽度：
    绝对定位 + 无宽度 = 收缩包裹，文字正好贴在 `left` 上；
    强行写死会把行盒撑宽，居中/右对齐的文字整体平移。
    现在只有计算宽度是具体值时才写 `width`。

43. **文字元素的「视觉范围」要用行盒量。** 块级元素的 `getBoundingClientRect()`
    默认撑满整行，而用户看到的只是那几个字。钉住时改用文字行盒的并集，
    实测示例课件上 5 个文字元素 pin 前后位移全为 **0**。

44. **判断「选中容器还是容器里的文字」要用文本量，不能只看有没有底色。**
    课件页面里到处是带底色的包装层，只看底色会把卡片也让出去。
    现在：容器文字量明显多于该处那段文字 → 它是壳子，让位给文字；
    否则容器优先（点卡片就选卡片）。

### 工作台顺手感（第四轮：光标与反馈）

45. **光标要回答「这里能做什么」。** 悬停时统一给 `move` 是不够的：
    文字元素应当给 `text`（双击就能改字），色块/图片给 `move`（拖得动），
    空白给 `crosshair`（可以拉框选），锁定的元素给 `not-allowed`。

46. **光标更新不能做「变化才写」的短路。** `pickAt` 在空白处返回 `null`（假值），
    配合悬停缓存很容易漏掉一次更新 —— 表现是「从元素移到空白，光标还停在 move」。
    改为每次移动都按本次命中结果直接写。

47. **拖动 / 旋转的光标父子两侧都要设。** 画布在 iframe 里，
    只改父页光标时，鼠标停在画布上看到的仍是帧内的光标。
    现在拖动时父子两侧都设成 `grabbing`，收尾时两侧都复位。

48. **编辑框的几何必须只有一个来源。** 选择框、拖动起点、缩放手柄、
    右侧检查器的 X/Y/宽/高、以及导出到 PPTX 的形状框，必须是同一个矩形；
    一旦某一处改用别的测量，框就会和指针「错位」。
    现在统一走 `visualBox()`（= 元素自己的边框盒）。
    曾经想让块级文字元素改用文字行盒，见下面第 50 / 51 条 —— 那条路已经拆掉。

### 工作台的坑（第五轮：浮层坐标系）

49. **写在 `.overlay` / `.guides` 里的坐标必须是「画布坐标」，不能再乘缩放。**
    `.stage` 宽高 1920×1080 且带 `transform: scale(zoom)`，而 `.overlay`（选择框 /
    框选矩形 / 浮动工具条）与 `.guides` 都是它的子节点 —— 浏览器已经替你缩放过一次了。
    早期 `refreshOverlay` 又按 `sr.left + x * zoom` 写入，等于**缩放被应用两次**：
    实测 zoom≈55% 时选择框只有正确尺寸的 **30%**，并且整体往右下偏出画布，
    看起来就是「编辑框和元素对不上 / 点不到手柄」。
    现在 `.overlay` / `.guides` 内部一律用画布坐标，夹取边界也从
    `window.innerWidth` 换成 `CANVAS_W / CANVAS_H`。

    为什么一直没被发现：拖动、缩放、框选命中测试走的都是**帧内坐标**，
    那条链路本来就是对的，所以所有交互回归全绿；
    只有「框画在哪」这一层是错的，纯功能断言量不到。

50. **别用 `getComputedStyle().width` 判断「宽度是不是 auto」。**
    它返回的永远是**解析后**的像素值（`"1088px"`），既不会是 `"auto"` 也不会是 `"50%"`。
    `visualBox` 里原来那句
    `cs.width !== 'auto' && !/%$/.test(cs.width)` 因此恒为真，
    底下的「贴文字行盒」分支**一次都没执行过** —— 一段看起来在做事的死代码。
    真要判断宽度是不是内容撑出来的，得比较**元素与包含块的可用宽度**。

51. **别拿字体行内盒当「视觉范围」的基准。**
    `Range.getClientRects()` 返回的是字体 ascent/descent 撑出来的行**内**盒，
    通常比元素的行盒更高（示例课件的 `h1`：行盒 145px、字体盒 175px）。
    拿它当基准，选择框上下都会比元素大一截。
    框准不准，要看它和**元素自身的盒子**是否重合，而不是和字体盒重合。
    加上第 50 条的「几何来源要唯一」，贴文字这条路已整体拆掉。

### 工作台的坑（第六轮：包含块与非标准尺寸）

52. **`left/top` 是按包含块解析的，不是按根元素。**
    绝对定位元素的包含块 = 最近的「position 不是 static」的祖先（`transform` / `filter` 也会）。
    课件里到处是 `position:relative` 的卡片壳，所以元素的包含块经常不是 `[data-wd-root]`。
    `pinElement` 一律按根元素偏移写 `left/top` 时，元素会**整体平移一个「包含块相对根的偏移」**：
    实测在兜底分页（single-body，根里堆着整篇 body）的样例上，
    **17 个元素里 12 个一被 pin 就跳位** —— `div.cell` 偏 (120,110)、`h3` 偏 (240,226)。
    这就是「点一下画布，排版直接错」。
    现在所有帧内坐标 ↔ `left/top` 的换算都过 `containingBlock()`，
    并且按规范把包含块的 `border-width` 加回去（绝对定位相对的是 **padding box**，
    而 `getBoundingClientRect()` 给的是 border box）。修完：0 个跳位。

    配套的坑：量这类问题必须**倒序** pin 一遍。
    逐个 pin 会让先 pin 的元素脱离文档流，**它的兄弟跟着挪**，
    于是后面元素测到的位移里混进了别人的影响 —— 正序 9 个「异常」里其实全是串扰。

53. **非 1920×1080 的源页面会被归一化到画布。**
    `bakePosition` 会按页面原生尺寸锚到 (0,0)，再按比例缩放：
    宽高比与画布一致 → 等比放大**铺满**（1280×720 这类直接填满）；
    不一致 → 等比缩到装得下再**居中留白**，绝不拉伸变形。
    副作用见第 58 条 —— 缩放会成为新的包含块。

54. **左栏不能在每次 commit 时全量重建。**
    `renderRail()` 原来每次都 `rail.innerHTML=''` 再逐个重建，而缩略图是**异步**回填的；
    `commit()` 里 `renderRail()` 与 `scheduleThumbs()` 还会连着各触发一次。
    旧的那批 `.then` 于是把 `<img>` 写进已经脱离文档的 `.thumb-box`，新建的盒子一个图都没有。
    现在：页数与页 id 都没变时**原地更新**，只动 active 态与标题；
    `renderRailThumbs()` 领 generation 号，回调落地时若已过期、或期间翻过页、或盒子被换掉，一律丢弃。

### 工作台的坑（第七轮：栅格化、时序与缩放）

55. **SVG data URI 是按 XML 解析的，`void` 元素必须自闭合。**
    缩略图走的是「计算样式内联 → 塞进 `<foreignObject>` → 当图片画到 canvas」。
    这段 HTML 最终成为 `data:image/svg+xml`，浏览器用 XML 解析器读它，
    而 XML 里没有「void 元素」这回事 —— `<br>` / `<img>` / `<hr>` 必须是 `<br/>`。
    HTML 序列化器不会自闭合它们，于是外层一遇到 `<br>` 就**整张图解不开**：
    实测一份 10 页课件里含 `<br>` 的两页缩略图**永久空白**，
    控制台只有一句「SVG 栅格化失败（图片解码错误）」，其余页面正常 —— 极难联想到。

    两个坑叠在一起：
    - 不能用 `el.outerHTML = '<br/>'` 修。`outerHTML` 的赋值器按 **HTML 上下文**重新解析，
      `<br/>` 在 HTML 里等价于 `<br>`，改完立刻变回非自闭合。只能在序列化后的**字符串**上替换。
    - 正则要能跳过引号里的 `>`：`/<(br|img|...)((?:[^>"']|"[^"]*"|'[^']*')*?)\s*\/?>/gi`。

    定位手法：把生成的 SVG 丢给 `DOMParser(..., 'image/svg+xml')` 读 `parsererror`，
    浏览器会直接告诉你第几行第几列、什么标签对不上。

56. **别在 `pointerdown` 就把元素 pin 掉。**
    `onFramePointerDown` 会直接进 `beginDrag`，而 `beginDrag` 里顺手 `pinElement` 了 ——
    于是「点一下不拖」也会把元素改成绝对定位，它脱离文档流，
    父级若是 auto 高度就当场塌掉。实测某份课件上连点三下，
    父容器高度 **376 → 222 → 151**，一层比一层矮，整页排版错乱。
    现在 pin 推迟到 `onDragMove` 里真正越过位移阈值时，由 `repositionElement` / 缩放分支去做。

57. **延迟落库的操作，会让撤销在窗口期内完全失效。**
    微调为了不刷屏用了 `debounce(commit, 500)`，但模型里的 `slide.doc` 在这 500ms 内还是旧的。
    用户在这段时间按 Ctrl+Z，`store.undo()` 因为 `hIndex === 0` 直接返回 false，
    表现是「撤销没反应」；等 debounce 到点，又把**改动之后**的快照推进去，
    于是之后按撤销也回不到原位 —— 实测就是「怎么按都没用」。
    凡是要读模型的动作（撤销 / 重做 / 保存 / 导出）都必须先 `flushNudgeCommit()`。
    序列化读的是**活的 DOM**，所以最稳的一刀是加在 `syncSlideDoc()` 开头。

58. **页面归一化到画布会引入 `transform`，而 transform 会成为新的包含块。**
    为了让 1280×720 这类源页面铺满 1920×1080，`bakePosition` 会加
    `transform: scale(1.5)`。但 CSS 里 `transform` 和 `position != static` 一样
    **会为后代建立包含块**，于是子元素的 `left/top` 要用页面自己的坐标系。
    不处理的话，页面一归一化，点任何元素都会整体跳位。
    所以 `containingBlock()` 必须同时返回缩放比，换算时先除以它：

        left = (x - cb.left) / cb.scale + cb.bl

    其中 `cb.bl` 是包含块的 border 宽度，属于**本地单位**，不参与缩放。
    归一化策略：宽高比一致 → 等比放大铺满；不一致 → 等比缩放居中留白，绝不拉伸。

### 工作台的坑（第八轮：入口收敛与文字编辑手感）

59. **`focus()` 必须在设选区之前，反过来会把光标冲掉。**
    `beginTextEdit` 先 `setRange` 再 `focus()` 时，`focus` 触发一次选区重算，
    刚设的 range 被折叠到文档开头 —— 表现是「双击进去了，但光标乱跳、选不中想选的字」。
    这是「改一个字要试好几次」的另一半原因。
    现在顺序固定为：设 `contenteditable` → `focus()` → `addRange()`。

60. **课件里的 `user-select:none` 会让双击选词彻底失效。**
    遮罩层常写 `user-select:none`，而 `contenteditable` 元素的选中行为会**继承**它，
    于是进入编辑态后鼠标拖选、双击选词全都没反应。
    `beginTextEdit` 现在显式写 `userSelect/webkitUserSelect = 'text'`，`endTextEdit` 再清掉。

61. **双击命中的不一定是该编辑的块。**
    `<h1>文字<em>强调</em></h1>` 这种写法里，`pickAt` 按第 22 条返回**最内层**，
    命中的是 `<em>` —— 行内排版标签，把它设成 `contenteditable` 会出现两个光标区。
    现在 `textBlockFor()` 从命中节点**向上**找最近的可编辑文字块；
    若命中的元素自己还含块级子元素，则用 `pickTextBlockInside()` 往里找真正的那段文字。

62. **光标落点要用 `Range` 自己算，不能依赖浏览器默认行为。**
    默认 `focus()` + `selectNodeContents` + `collapse(false)` 会把光标丢到末尾，
    和双击的坐标完全无关。新增 `caretPositionAt(node, x, y)`：
    在元素内用 `caretRangeFromPoint` 找到离点击点最近的插入点，
    失败时回退到「全选内容」再折叠，双击至少会落在被点的那个词上。

63. **手柄要「放大抓取热区」，不是「放大视觉尺寸」。**
    视觉手柄从 10px 提到 13px（旋转手柄 18px → 22px）已经接近上限，再大就压住元素内容；
    真正的做法是给手柄加 `::before` 伪元素撑出 24px（旋转 30px）的**透明抓取区**，
    配 `hover/active` 过渡 —— 点得中，又不喧宾夺主。
    （视觉尺寸本身还要吃 `scale(1/zoom)` 反向缩放，见第 25 条。）

64. **面板收起按钮要「贴在卡片内侧边缘、上下居中」，不能放面板头部。**
    放 `.panel-head` 里时，折叠后 `display:none` 会把它一起带走（第 39 条）。
    现在它是面板的**直接子元素**，用 `top:50% + margin-top:-26px` 定位到视口垂直中线，
    正好和用户的视线落点一致 —— 这是位置，不是样式问题。

65. **格式刷只能搬「视觉属性」，且必须是一次性的。**
    连 `left/top/width/height` 一起搬的话，目标元素会被顶到源元素的位置上；
    连按几次又会把手柄刷没。现在只搬 `PAINT_PROPS`（颜色 / 圆角 / 边框 / 阴影 / 字体 / 字号），
    且**用一次即失效**（`setPainterActive(false)`），避免误连点刷成一色。

66. **合并入口后，旧测试会指向已删除的 DOM。**
    「添加元素」从右栏搬到顶栏插入组，`#add-grid` 整个消失，
    `edit-test2.mjs` 段 `[13]` 一旦还按旧 id 查询就会**假失败**（找不到按钮 ≠ 功能坏了）。
    同理，自动化里凡是量「按钮是否展开」都要等 `menu-in` 动画结束再量 `getBoundingClientRect()`。

67. **测试自己插进去的元素会留在截图里，看着像渲染缺陷。**
    插入组用例在画布正中插了个 420×260 的浅色矩形（`rect` 的默认底色 `rgb(232,238,247)`）。
    它不只盖住标题，**缩略图里也会同步出现同一块白斑**，
    于是「验收截图里有块莫名其妙的白框」很容易被当成 z-index / iframe 合成问题去查，
    实际 DOM 里根本没有这个东西。
    定位办法是别猜、先量：`[data-wd-added]` 的元素在帧内可枚举，
    实测它的屏幕盒子 `[623,368,227,140]` 与白框逐像素吻合，底色也对得上。
    现在插入组用例断言完就把自己插的元素清掉，截图恢复干净。

68. **两个 `flex:1` 的兄弟节点会平分空间，`justify-content:center` 只在自己的那一半里居中。**
    左栏是 `flex-direction:column`，`.rail`（幻灯片轨）和 `.rail-empty`（空状态提示）
    都写了 `flex:1`。没载入文档时 `.rail` 虽然一个子节点都没有，
    **仍然会分走一半高度**，于是空状态只拿到下半区。
    它自己的 `justify-content:center` 确实生效了 —— 但那是「下半区的中心」，
    整栏看下来明显偏下，实测内容中心比轨道区中心低 **188px**。
    修法是让空轨不占位：`.rail:empty { flex: 0 0 auto; padding: 0; }`，
    载入文档后 `.rail` 非空、`:empty` 不再命中，行为完全不变。
    复测 1600×950 与 1100×1400 两种窗口，偏差均为 **0px**。

    教训：**「我明明写了 `justify-content:center`」不等于「它居中了」** ——
    必须量内容外接框的中心与容器中心的差值，光看代码永远看不出来。

### 工作台的坑（第九轮：顶栏扁平化）

69. **「不显示边框」要真的写成 `border: 0`，不能靠 `transparent` 糊弄。**
    第一版给顶栏按钮写的是 `border: 1px solid transparent` —— 肉眼看不出边框，
    但自动化一量 `getComputedStyle().borderTopWidth` 就是 4px（1px × 四边），
    「无边框」这条断言直接红。后来还发现它有个真实副作用：想给激活态换个 `border-color`
    时，宽度从 0 跳到 1px，按钮会**抖一下**。
    现在基础态就是 `border: 0`，激活态用 `box-shadow: inset 0 0 0 1px` 画内描边，
    宽度恒为 0，既不显示也不会抖。

70. **图标不要用 emoji。**
    emoji 走的是系统彩色字体，字形和基线都不可控：和 12.5px 的中文标签并排时明显歪，
    深色主题下还要单独换一套彩色 emoji，而线性图标只要 `stroke: currentColor` 就自动跟随主题。
    现在是 shell 顶部一份 `<symbol>` 图标集 + `<use>` 引用，14 个图标共用一套描边参数。

71. **线性图标自己也要看放大图。**
    「标题」图标最初是「T + 一条底横线」，4 倍放大一看，
    那个组合在中文语境下直接读成汉字**「工」**，根本不像「标题」。
    这类问题在 1:1 截图里看不出来，**必须放大到 3–4 倍逐个核对**。

72. **flex 子项默认都能压缩，顶栏一变宽就会把徽章压成竖排。**
    按钮全改成「图标 + 文字」之后，顶栏宽度吃紧，
    flex 默认的 `flex-shrink: 1` 会把不够用的宽度**摊给所有兄弟节点**，
    结果「有未保存修改」这个没有省略号兜底的元素被挤成竖排一字一行。
    现在固定内容一律 `flex-shrink: 0`，只有文件名胶囊可缩（它有 ellipsis 兜底），
    空隙交给 `.tb-spacer` 吸收。

    补充（第十一轮）：这个独立徽章后来撤掉了，未保存提示并入文件名胶囊（见坑位 81）。
    胶囊改成 flex（点 + 文件名）之后，文件名必须单独包一层 `<span>` ——
    flex 容器里的**匿名文本节点无法套 `text-overflow: ellipsis`**，
    不包起来长文件名就会直接顶破胶囊而不是被省略号截断。

73. **给祖先加 `overflow` 会顺手裁掉 absolute 的下拉菜单。**
    顶栏改成横向滚动容器（见第 74 条）之后，下拉菜单一展开就只剩一条边 ——
    `position: absolute` 的后代会被祖先的 overflow 直接裁掉，没有任何报错。
    修法是把菜单与查找栏改成 `position: fixed`，坐标在 `showMenu()` 里现算并夹取到视口内；
    `fixed` 的包含块是视口，不受滚动容器裁剪。
    顺带加了「顶栏滚动 / 窗口缩放时自动收起菜单」，否则菜单会跟着按钮飘走。

74. **按钮变宽之后，顶栏在 1280–1600px 的笔记本上装不下，必须能横向滚动。**
    实测 1600px 视口下，文字格式条一出现（它是最高频触发的「变宽」来源）
    顶栏就超出 **159px**。现在 `.topbar` 是 `overflow-x: auto` 的滚动容器、滚动条隐藏，
    触控板 / Shift+滚轮都能推。
    日常状态（没选中文字）宽度是 1391px，1600px 视口仍然完整显示、不触发滚动。

### 工作台的坑（第十轮：删按钮与下拉只能开一次）

75. **「打开」不能只靠一个按钮：删掉顶栏按钮等于删掉换文件的能力。**
    顶栏「打开 HTML」按要求移除后，载入文档之后就没有任何入口能换文件了。
    现在打开入口落在三处：空状态按钮、「保存与导出 ▼」菜单第一项、`Ctrl+O` / 拖拽。
    同理，「面板」总开关按钮移除后，一键显隐改绑到 `Ctrl+\`，
    单侧收起仍由卡片边缘的拉手负责 —— 删 UI 不等于删功能。

76. **下拉「只能下拉一次」：两个独立原因叠在一起。**
    - `closeMenus()` 忘了 `openMenu = null`，于是它一直指着那个**已经 hidden** 的菜单；
    - 全局兜底用的是 `document.addEventListener('click', …, true)`，**捕获阶段**会先于
      触发按钮自己的 handler 执行。于是「第二次点击」先被兜底关掉，
      紧接着按钮又把它打开 —— 状态判断永远读到「本来就开着」，
      表现就是：开 → 关 → **第三次再也打不开**。

    修法两条一起：`closeMenus()` 里置空 `openMenu`；
    全局监听从**捕获**改成**冒泡**（触发按钮已经 `stopPropagation`，冒泡阶段走不到那里），
    再补一个 `trigger.contains(ev.target)` 判断兜住将来的其它触发器。
    「开还是关」只看 `menu.hidden`，不看 `openMenu` —— 后者会被兜底逻辑抢先改掉。

    **为什么之前没测出来**：旧用例只点了两次（开 → 关）就结束，
    恰好停在还能工作的那一段。现在必须连点满 6 次，
    并且额外覆盖「点外面关掉后还能再打开」和「Esc 之后还能再打开」两条路径。

77. **把文件选择器藏进能力里，而不是藏进形状下拉。**
    图片、视频要弹系统文件选择器，属于「独立能力」：
    混在「形状」里既容易被误点，也让那个下拉名不副实（里面根本没有「文件」）。
    现在是顶栏两个平级按钮，形状下拉只剩 5 种真正的形状。

78. **视频不能内嵌进工程文件，必须把代价讲在前面。**
    视频动辄几十 MB，塞进单文件 HTML 会直接撑爆；而 `blob:` / `objectURL`
    在重新打开工程时必然失效。现在的取舍是：
    本次会话内用 `objectURL` 真正可播放，同时**抓首帧存成封面图（poster）**，
    于是画布、缩略图、PPTX 贴图在会话结束后仍然正确；
    导出 PPTX 时它与「渐变 / 阴影 / 旋转」一样按封面贴图处理。
    真正的可编辑视频需要写 OOXML 的 `p:pic` + 媒体关系 + 嵌入文件，不在当前范围内。

79. **「抓首帧当封面」抓到的是黑图 —— 而且 DOM 看起来完全正常。**
    这是本项目最隐蔽的一个坑：代码在 `loadeddata` 里 `drawImage(v, …)` 抓首帧，
    抓完 `poster` 确实写进去了、是一段合法 JPEG data URI、长度 1515 字节，
    所有「结构上有封面」的断言全部通过，画布上却是一块纯黑。
    量像素才看清：MediaRecorder 录出的 WebM，**第 0 帧整幅非黑像素占比 0%**，
    `t=0.2s` 起才恢复正常画面（实测非黑占比 1.0）。摄像头与不少转码流同样先塞一帧黑场。
    修法是「先量再抓」：把当前帧缩到 32×18 抽样，非黑像素低于 2% 判为废帧，
    按 `0 → 0.12 → 0.3 → 0.6` 秒逐个 seek 重抓；`seekable` 为空（极短视频 / 直播流）
    就直接认了，绝不空等。再加 5 秒兜底，保证元素一定会被提交、不会永远缺封面。
    教训有两条：**断言「有个 poster」不等于断言「poster 是对的」**，
    得解码出来数像素；以及 **`if (!t)` 里 `t = 0` 是假值** ——
    我第一版修复把停止条件写成「没有下一档时间点」，结果 `OFFSETS[0] === 0`
    在第一次废帧后就把整条抓帧链放弃了，封面直接变成 0 字节。停止条件要看**下标**，不看值。

80. **同一层里的元素，会不会被画布缩放连坐，取决于有没有做 counter-scale。**
    选中元素后的浮动工具条一直没人反馈过问题，直到用户发来一句「太小了看不清」。
    量出来才发现：CSS 明明写着 `width: 26px`，**屏幕上实测只有 14×14** ——
    因为工具条在 `.overlay` 里，而 `.overlay` 位于 `transform: scale(0.55)` 的 `.stage` 内，
    尺寸被缩放打了折；里面的字形又只有 12.5px 的 Unicode 符号（`✎ ⧉ ⇧ ⇩ ✕`），
    打折之后笔画细到 `⇧` 只剩两笔。
    手柄（`.handle`）早就用 `transform: scale(var(--wd-inv-zoom))` 治过同一个病，
    还专门写了注释 —— **但同一个 overlay 里的工具条和标签都漏了**。
    现在三处统一：工具条与标签都 counter-scale，图标换成与顶栏同一套内联 SVG
    （见坑位 70：Unicode 符号在 12.5px 下又细又难辨）。
    实测按钮从 14×14 变成恒定 30×30，在 100% / 75% / 50% / 35% 四档缩放下都不再变化。
    顺带修掉一个同源的隐患：JS 里写死的 `BAR_W = 150` / `barH = 34` 是**按旧尺寸估的**，
    工具条变宽 22px 后贴边夹取就会算错。已改成 `bar.offsetWidth/offsetHeight` 实测
    —— `offsetWidth` 不受祖先 transform 影响，而 scale 已被自身抵消，拿到的正好是屏幕真实尺寸。
    教训：**量尺寸要量 `getBoundingClientRect()` 的屏幕值，不能读 CSS 里写的数字。**

81. **「文件名」和「它是不是最新」是同一件事，分成两处提示等于让人来回扫视。**
    原先顶栏左侧常驻一个「有未保存修改」徽章，右边又有一个 `cw_33.html` 胶囊 ——
    两个胶囊、同一排、同一种圆角，说的却是同一份文稿的两种状态。
    现在撤掉独立徽章，未保存提示并入文件名胶囊：有改动时前面亮起一个 6px 琥珀点，
    同时文字转成强调色，悬停给出 `title="有未保存的修改"`（点没有文字，得配 title 才不至于让人猜）。
    两个实现细节：
    - 点用 `display: none` 而不是 `opacity: 0`。后者会让胶囊**永远**多出 13px 空隙，
      看着像左边塌了一块；前者只在真的有改动时才变宽，多出来的宽度由 `.tb-spacer` 吃掉，
      别的控件不会移位。
    - 撤销**不会**让点消失：`store.undo()` / `redo()` 里都显式 `setDirty(true)`，
      「撤销本身也算一次改动」是这个库既定的语义（Office 那种
      「撤销回上次保存的状态就自动干净」这里没做）。点真正消失是在**保存**之后。
      写回归时别按 Office 的直觉去断言，否则会得到一条永远红的用例。
    - `min-width: 0` 会让这个点**在最需要它的时刻消失**。选中文字元素后文字格式条出现，
      顶栏变宽，胶囊是顶栏里唯一带 `flex-shrink` 的元素，被一路压到 24px；
      而胶囊自身 `padding` 就占 22px，内容盒只剩 2px，
      那个 6px 的点被 `overflow: hidden` **整个裁掉** —— 正在编辑文字的人反而看不到未保存提示。
      实测逐档扫过：`min-width` 低于 40 点就不完整，56px 是平衡点
      （点 6 + 间距 7 完整可见，再留 19px 给文件名走省略号）。
      代价是 1600px 视口下顶栏多溢出约 49px，但正常状态（没选文字）宽度正好 1600，完全不滚动。
      这类「挤压后失效」的缺陷，肉眼在小窗口里根本看不出来，**必须去量内容盒**。

### 工作台的坑（第十二轮：形状约束与元素能力层）

这一轮的六个新元素（表格 / 公式 / LaTeX / 三种图表 / 竖向文本框）把一个原本不存在的
问题顶到了台面上：**以前所有元素都能自由拉伸，所以「缩放」只有一条路径；
现在有了圆形和线条，必须先回答「这个元素允许被改成什么样」。**

82. **圆形和椭圆是两种东西，不该共用同一条拉伸路径。**
    最早它们是同一个 kind（`border-radius: 50%`），于是「圆形」拖一下角就变成椭圆 ——
    因为对圆形来说，任何一次拖角都是在自由改宽高。
    现在拆成 `circle`（锁宽高比，怎么拖都是正圆）与 `oval`（自由拉伸）两个 kind，
    约束统一收在 `07-elements.js` 的 `applyConstraint(node, start, next, handle)`：
    `{ ratio: 'w/h' }` 锁比、`{ lockH: 26 }` 锁死高度、`null` 自由。
    实测圆形拖角后仍为正圆，检查器改宽 500 得 500×500。

83. **约束比例必须用「拖动开始时的 start」算，不能在被约束的元素上就地重测。**
    调用方的顺序是「量 start → 算 next → `pinElement` 写回」，而 `pinElement` 本身会改变盒子。
    于是约束函数里再量一次得到的是**另一个**盒子，两个盒子互相矛盾 ——
    实测把圆形宽度改成 500，高度被算成 **423**（既不是 500 也不是原始的 260）。
    这类 bug 特别难查，因为「确实变了一点」，只是变成了一个说不出来的数。

84. **同一个约束必须同时管住手柄和检查器输入框。**
    只改手柄分支的话，用户从右侧「宽/高」输入框改尺寸照样会把圆形改扁。
    现在两条路径都走 `applyConstraint`，`refreshOverlay` 再用 `deadHandles(node)`
    把对该约束**无意义的手柄直接隐藏** —— 直线只留左右四个（h=6），
    箭头类只留左右两个（h=26）。让用户看不到死按钮，比点了没反应好。

85. **约束对象的键名与 DOM 的键名不一样，这是个阴险的坑。**
    约束里存的是短键 `w` / `h`，而 DOM 上是 `width` / `height`。
    写 `next[pair[1]] = v`（`pair[1]` 恰好是 `'width'`）会写到**没人读的属性**上：
    元素纹丝不动，输入框却老老实实显示 500，没有任何报错。

86. **箭头不能用 `clip-path`，也不能用 `<marker>`。**
    `clip-path` 用百分比 → 箭头头部跟着宽度一起被拉长，拖宽之后完全变形；
    `<marker>` 的定义挂在文档级 `<defs>` 里，帧 iframe 重载后 `url(#id)` 容易指向旧文档，
    箭头会凭空消失。现在是**固定像素箭头 + 可拉伸杆**画成的 path
    （`HEAD_W=16` / `HEAD_H=8` / `SHAFT_T=3`），每次 `refreshOverlay` 调 `syncLine` 重画，
    改色也跟着走。直线/箭头/双向箭头实测斜拖 120px 纵向分量后高度纹丝不动。

87. **三角形与平行四边形用 `clip-path`，而箭头不用 —— 因为箭头是「一维」的。**
    前两者是实心色块，裁剪路径随盒子缩放自适应；箭头带头部，缩放会破坏比例，
    所以只能走上一条固定像素的路子。同一批「形状」里混着两种机制，
    写的时候务必分清楚，否则「圆形为什么不用 clip-path」会变成新的谜题。

88. **单文件离线装不下 KaTeX，公式只能走原生 MathML。**
    Chrome 109+ / Edge / Firefox 有 MathML Core，够用；代价是更老的 Chromium 会退化成源文本。
    解析器（`latexToMathML`）里有个极隐蔽的坑：**包装函数的键名必须是 `t`**。
    写成 `{ m: kind }` 时，`toMathML` 按 `n.t` 分派永远走 default 返回空串 ——
    公式看上去「渲染成功了」（外层盒子在、字号对），但**上下标被整段吞掉**。
    实测 `\frac{-b \pm \sqrt{b^2-4ac}}{2a}` 解析出 `<mfrac>` + `<msqrt>` + 上下标。

89. **LaTeX 的分组 `{…}` 必须在 tokenizer 阶段整段吞掉并保留原文。**
    若放到 parser 里做花括号深度计数，`\text{未闭合` 这种输入会**死循环**；
    而按空白切 token 时，`\text{当 }` 里那个用来分隔的空格会被当成空白吃掉。
    现在 tokenizer 遇到 `{` 就一路扫到配对的 `}`，整体作为 `grp` token 落库。

90. **表格改行列不能用 `innerHTML` 重建 —— 选区引用会全部失效。**
    现在是「按新尺寸 rebuild + `replaceChild`」保住节点身份，再把已有单元格内容搬回去，
    这样刚插入的表格改完行列仍然是选中状态。类似的，**单元格文本要能被双击编辑**，
    走的是既有的 `beginTextEdit` 链路，不另起一套。

91. **图表用 canvas 画完 `toDataURL` 插成 `<img>`，而不是画成矢量。**
    缩略图、PPTX 导出、放映三处都只需要「一张图」，各自适配矢量要写三遍；
    canvas 在任意缩放下都锐利，改数据重画也简单。代价是图表在 PPTX 里不可编辑，
    与「渐变 / 阴影 / 旋转」同级处理。

92. **`position: fixed` 的下拉只夹右边不够，贴齐右边缘时会溢出视口。**
    原来的 `positionMenu` 是「若 `left + 宽` 超视口就整体左移到贴边」，
    但顶栏改版后保存菜单正好落在视口右侧，`l` 已经是 1458，再左移会把触发按钮甩到视野外。
    现在**双边夹取**：`left` 夹在 `[8, vw - w - 8]`，`top` 夹在按钮下方到视口底。

93. **表格单元格写死 `width` 会被自己的 padding 顶开 —— 而且是 `content-box` 干的。**
    每个 `td` 都写了 `width: 200px`，可单元格默认是 `content-box`，
    `padding: 6px 10px` 与折叠边框**额外**累加：5 列实际需要 `5×(200+20)+6 = 1106px`，
    比表格自己声明的 `1000px` 还大，于是 `table-layout: fixed` 完全失效 ——
    实测「检查器里把宽改成 620」看着成功了，**元素纹丝不动**。
    现在统一 `box-sizing: border-box` 且**不写死单元格尺寸**（交给 fixed 布局等分）。
    教训：`offsetWidth` 才是布局真值，读 `style.width` 只能读到一句一厢情愿的话。

94. **`<foreignObject>` 已经按盒子原点平移过了，克隆树里不要再带 `left/top`。**
    `buildSvg` 写的是 `viewBox="x y w h"` + `<foreignObject x="x" y="y">`，
    而 `cloneWithInlineStyles` 又把根元素的计算样式（含 `left:590px; top:290px`）原样搬了过去 ——
    **偏移被应用两次**，内容整个落到 `foreignObject` 之外，栅格化出来是一张全透明的 PNG。
    实测三角形 / 平行四边形 / 直线 / 箭头在 PPTX 里**全是纯白**，画布上却完全正常。
    缩略图一直没暴露：那条路的根元素本来就在 `(0,0)`。
    现在根克隆一律抹掉 `left/top/right/bottom`（**保留 `position`**，否则后代又得偏移一次）。

95. **克隆树被当 XML 重新解析时，`<svg>` 不会自动进 SVG 命名空间。**
    HTML 解析器看到 `<svg>` 会切命名空间，XML 解析器不会 ——
    它老老实实继承 `<div xmlns="…xhtml">` 的默认命名空间，
    于是 `<svg>` / `<path>` 变成两个普通的 XHTML 元素，**一个像素都不画**。
    必须在 SVG 元素的源头显式补 `xmlns="http://www.w3.org/2000/svg"`（子元素靠继承）。
    与第 55 条同源：**这段 HTML 最终是按 XML 解析的**，凡是只在 HTML 语境下成立的东西都要重新验证。

96. **补命名空间时别漏了根节点。**
    导出「线条」这类元素时，送给栅格化器的节点是**内层那个 `<svg>`**（它自己就是克隆树的根），
    于是补丁恰好跳过了它 —— 箭头在 PPTX 里永远是空白，而画布上完全正常。
    对照实验才能定位：同一个元素在「舞台帧」里栅格化有像素、在「导出用的挂载帧」里没有，
    一层层把变量砍到只剩一个（`src.namespaceURI === SVG_NS` 且根节点也要补）才收敛。

97. **定位这类问题一定要做「逐级简化」的对照实验，不要读代码猜。**
    本轮一连三个结论都是反直觉的（偏移翻倍 / 命名空间 / 漏根节点），
    靠读 `rasterizeNode` 完全看不出来。有效的做法是构造 A–G 七个只有单一差异的最小 SVG，
    逐个数非白像素：最小红块 25% → 加 `position:absolute` 0% → 加 `clip-path` 12.75%
    → 去掉 `left/top` 100%。**每个箭头都指向一个可验证的量。**

### 工作台的坑（第十三轮：下拉、图表文字与「可编辑」的边界）

98. **下拉项改成「左图标 + 右文字」时，别把旧 class 换掉。**
    五个插入组（形状 / 标题 / 文本框 / 公式 / 图表）各有自己的菜单容器，
    既有测试是按 `#menu-title .shape-row button` 选的，还断言了按钮的 `title` 属性。
    现在 `bindKindMenu` 渲染成 `<button class="menu-item"><span class="mi-ico">…</span><span class="mi-txt">…</span></button>`，
    但**容器仍然保留 `shape-row` 这个 class 和 `title` 属性** ——
    纯视觉改造不该逼着改五个测试文件的选择器，那会让「功能坏了」和「选择器过期了」混在一起。

99. **图标本身也要区分开，否则「左图标 + 右文字」是白做。**
    最早的版本里四个标题项的图标都是 `H`，两个文本框都是 `T`，四项长得一模一样。
    现在是 `H1/H2/H3/H4` 与 `↔/↕`。回归里专门钉了一条「四个标题的图标互不相同」。

100. **公式就该是个纯文本框，不要给它加壳。**
    第一版给公式套了白底 + 虚线边框 + 圆角，看起来「像个卡片」，
    但用户要的就是「插入公式 = 一个文本框」：公式自己的颜色、字号、行高就该是全部的外观。
    现在 `background: transparent` / `border: none` / `border-radius: 0`。
    实测 `bg=rgba(0,0,0,0)`、`borderTop=0px`、`radius=0px`。

101. **表格数据格点不中的根因是「按元素找格子」，而不是「按坐标找格子」。**
    双击处理一直是「拿落点去匹配文字块」，而 `textBlockFor` 要求单元格**已经有文字**才返回 ——
    空表格只有表头有字，于是数据行怎么点都没反应。
    现在加了 `cellAt(x, y)`：`elementFromPoint` 取到最深节点后向上找最近的 `TD/TH`，
    并让 `textBlockFor` 遇到 `TD/TH` 直接返回。回归里特意先自证「双击点确实落在第 3 行第 2 列」
    （`row=2, col=1`），否则测出来的可能只是「点歪了」。

102. **图表的标题槽与图例槽要固定，不能「有就画、没有就缩」。**
    第一版是标题存在才占高度，于是**改个标题图形就跳半屏**，用户会以为刚点的位置没生效。
    现在 `CHART_HEAD = 56` / `CHART_LEGEND = 44` 恒定占位，有内容就画字、没有就留白，
    绘图区位置永远不动。实测开关图例前后柱顶高度不变。

103. **量贴图的「墨量」必须先把网格线和柱子排除掉。**
    验证「标题画上了没有」时，量整张图的非白像素是**无效的**：
    去掉标题 → 绘图区变高 → 柱子变高 → 墨量不降反升。
    正确做法是只数文字色的像素：`r<110 && g<115 && b<140`
    （标题 `#16202e`、图例文字 `#4a5a70` 会被数到，网格线 `#d8e0ea`、刻度 `#7c8ba1`、柱子 `#3b6fd4` 不会被）。
    实测带标题 174 个深色像素 → 关标题 0 个；图例同理。

104. **透明底 PNG 只能量 alpha 覆盖率，量 RGB 会把透明当成有墨。**
    透明像素的 RGB 是 `0,0,0`，所以「非白像素」会把整张图算成 99.9%。
    形状栅格化的断言改成数 `alpha > 0` 的像素，实测正圆 78.67%（≈ π/4）、
    三角形 50.17%（≈ 1/2）、直线满格 —— 数字和解析解对得上，才算真的在断言形状。

105. **弹窗的标签列要按最长文案量宽度，不是拍脑袋给个「够宽」。**
    `.form-lbl` 原本 56px，「系列与数值」实测 **63px**，于是折成两行还掉一个孤字「值」，
    看着像 bug。文案「分类（逗号分隔）」（100px）更是断在词中间。
    现在标签列 76px，并把提示挪进输入框的 `placeholder`。回归里加了一条
    「数据表标签一律单行不折断」：逐个量 `height / line-height` 的行数。
    ⚠️ 别一上来就信缩略图里看到的「LaTe / X 折行了」—— 裁图放大 3 倍才看清它其实一直是单行，
    **`getBoundingClientRect()` 量的是盒子宽度（被 `width:56px` 写死），量不出文字本征宽度**，
    要量文字得临时把 `style.width` 改成 `auto` 再读。

106. **CDP 发的鼠标坐标是顶层页面坐标，元素的 `rect` 是 iframe 视口坐标。**
    脚本里直接 `frameRect + x` 会点在隔壁元素上，测出来的是「点歪了」而不是产品缺陷 ——
    这种「假失败」最费时间。正确换算是
    `page = frameRect.left + x * (stage.fitMode ? stage.scale : stage.zoom)`。
    这条同时解释了为什么「双击图表弹不出对话框」一度看起来像功能没生效。

107. **「改完立刻生效」的测试要断言两件事：`src` 变了 **和** 模型写回了。**
    图表数据表编辑器如果只重画了 canvas 却没把 JSON 写回 `data-wd-chart`，
    下次双击打开的还是旧数据 —— 界面上「改成功了」，重开就丢。
    现在 `repaintChart` 先 `normalize` 再 `setAttribute('data-wd-chart')` 最后 `img.src = toDataURL()`，
    回归里「改完标题立即生效并写回数据模型」同时断言 `src` 变化与 `JSON.parse(attr).title` 一致。

### 自动化测试自身的教训

37. **测试用例之间必须隔离。** 前一个用例把元素挪走了，后一个用例就会点到空处，
    然后报出一堆「功能坏了」的假失败。每个用例前重置画布 + 关浮层 + 等舞台就绪。

38. **不要把「断言用的数据」和「展示用的数据」混在一个字段里。**
    我把 `made` 写成了名字数组、几何放在 `madeFull`，断言读 `made` 于是一直失败 ——
    看起来像产品 bug，其实是测试写错了。断言失败时先确认读的是不是自己想读的字段。

## 已知限制

- **跨域素材**（图片 / 字体）读不到内容会被跳过；本地文件与 `data:` URI 不受影响。
- **自定义 `@font-face` 不嵌入 PPTX**。文字保真取决于演示电脑上是否装有对应字体；
  引擎已为中文单独声明 `eastAsia` 字体以降低回退风险。
- **动画与交互**不会进入 PPTX（静态导出）；放映模式可以放原始 HTML 动效。
- **表格、列表等内容会被还原成文本框与形状，而不是 PowerPoint 原生表格对象。**
  新插入的表格同理：每个单元格导出成一个真文本框（可改字），
  外加一个表格底框，PPTX 里**没有** `a:tbl`。实测一份 4×5 的表 = 25 个单元格文本框。
- **公式导出成普通文本运行，不是 OMML 公式对象。** MathML 里的 `mi/mn/mo`
  会被拆成若干可编辑的文本运行（能改字），但上下标、分式、根号在 PowerPoint 里
  不再是「公式」而是普通字符。想在 PPT 里继续当公式编辑，需要另写 OMML 转换，不在当前范围内。
  另外公式在**画布内**依赖浏览器的 **MathML Core**（Chrome 109+ / Edge / Firefox）；
  更老的 Chromium 上会退化显示 LaTeX 源文本 —— 单文件离线装不下 KaTeX，这是有意的取舍。
- **图表按 PNG 贴图导出**（`p:pic`），不可在 PPT 里改数据 —— 与「渐变 / 阴影 / 旋转」同级处理。
  画布**内**是完整可编辑的：双击弹出数据表，改完立即重画，数据 JSON 存在元素属性里跟着工程一起存；
  但导出的 PPTX 里它是一张图，在 PowerPoint 里点不开数据表。
- **三角形 / 平行四边形 / 直线 / 箭头 / 双向箭头也走贴图**（它们依赖 `clip-path` 或内嵌 SVG，
  没有对应的 `prstGeom` 预设），视觉 100% 一致但不可再编辑。
- **视频只保留封面，不进入工程文件也不进入 PPTX。** 单文件 HTML 装不下几十 MB 的视频，
  而 `blob:` 地址重新打开工程时必然失效。所以本次会话内用 `objectURL` 真能播，
  同时抓一帧存成 `poster`：画布、缩略图、PPTX 贴图在关掉页面后依然正确，
  但在 PowerPoint 里打开导出的文件时看到的是一张静态封面图，不能播放。
  极短（不足 0.12 秒）或还在直播的流没有可 seek 的区间，封面只能取第 0 帧 ——
  若那一帧是黑场，就会得到一张黑封面。

## 品牌 Logo

顶栏与空状态用的是正式 logo（内嵌 data URI，仍然完全离线、单文件）。

原始图是一张 1254×1254 的方形图：一个浅色圆形底板 + 图标 + 「WizDeck」渐变字。
需要去掉圆形底板，但**不能按颜色抠** —— 图标里的「卡片」本身也是接近白，
与底板几乎同色（实测底板内部 ≈251，卡片内部 ≈247，四角背景 ≈251）。
按颜色或按径向渐变建模都会把卡片一起吃掉，或留下一圈方形/圆形的残影。

最终做法与取舍：

1. 从图像四边向内插值出「干净背景场」；
2. alpha = 该像素比背景场暗多少（圆盘边缘比背景暗 4~5 级，内容通常暗得更多）；
3. 阈值取 9~15：圆盘边缘彻底消失，图标本体与文字完整。
   代价是丢掉图标最外圈极淡的柔光 —— 圆盘边缘与柔光亮度区间重叠，
   客观上无法两全，做 UI logo 时「无底」比「保全部柔光」更重要。
   四档阈值的对比图当时存为 `brand/_sweep.png`（已清理）。

产出（`brand/`）：

| 文件 | 用途 |
| --- | --- |
| `wizdeck-mark.png` | 图标，透明底 512² |
| `wizdeck-wordmark.png` | 文字，透明底 |
| `wizdeck-lockup.png` | 竖排组合，透明底 |
| `app-icon.png` | 浅色圆角底的方形图标（256²） |
| `embed-*.png` | 按尺寸优化后的内嵌版本（调色板量化压体积） |
| `preview-app-*.png` | 贴在真实配色上的预览，用于验收 |

**浅色主题用透明版**（应用底色 #ffffff / #f5f7fa 与源图底板同色，接缝不可见）；
**深色主题换成带浅色底的版本** —— 透明版在深底上会散架，
因为图标的白色卡片与柔光本来靠浅底衬托，所以深色用浅色圆角底是必要的。

### 导出器的内置自查

导出时会在打包前做两层自检，任一不通过都会把问题写进 `warnings` 并在控制台报错：

1. **每个 XML 部件良构性 + 主要标签配平**（`validateParts`）——
   防止再出现「一个标签少了 `>`，所有文本框被渲染器丢弃」这类事故。
2. **ZIP 字节流回读比对**（`ZipWriter.verify`）——
   逐条核对压缩大小、原始大小与 CRC，并复算存储条目的 CRC。

### 编辑方式

| 操作 | 方式 |
| --- | --- |
| 选中 | 单击元素 · Shift+单击多选 · 空白处拖动框选 · Ctrl+A 全选本页 · Esc 取消 |
| 移动 | 拖动 · 方向键 1px · Shift+方向键 10px · 自动吸附并显示参考线（Alt 临时关闭） |
| 缩放 / 旋转 | 拖四角手柄 · 拖顶部圆点旋转（Shift 吸附 15°）。**圆形**锁宽高比，怎么拖都是正圆；**椭圆**自由拉伸；**直线 / 箭头 / 双向箭头**锁死高度（6 / 26 / 26px），八个手柄里只留左右那几个可拖 |
| 改文字 | 双击元素直接编辑（双击落在哪个词上，光标就落在那个词），Esc 退出 |
| 文字格式 | 顶栏格式条（选中文字元素时出现）：加粗 / 斜体 / 下划线 · 字号 A− A+ · 对齐 · 文字颜色 |
| 复制删除 | Ctrl+C / Ctrl+V / Ctrl+D · Delete |
| 图层 | 右侧「图层」面板可点选、拖拽重排、锁定、隐藏；Ctrl+] 上移 · Ctrl+[ 下移 |
| 插入 | 顶栏插入组（每项都是「左边图标 + 右边文字」的下拉）：**文本框 ▾**（横向 / 竖向）· **标题 ▾**（一 / 二 / 三 / 四级）· **形状 ▾**（矩形 / 圆角矩形 / 圆形 / 椭圆 / 三角形 / 平行四边形 / 直线 / 箭头 / 双向箭头）· **表格**（弹窗自定义行列）· **公式 ▾**（插入公式 / 插入 LaTeX，弹窗输入并实时预览）· **图表 ▾**（柱状图 / 折线图 / 饼状图）· 图片 · 视频 |

### 界面布局（对齐 bento 的约定）

```
┌───────────────────────────────────────────────────────────────────────────────────────┐
│ 新建页 │ 文本框▾ 标题▾ 形状▾ 表格 公式▾ 图表▾ 图片 视频 │ 格式刷 查找 │ …文字格式条… │ 保存与导出▼ │ 放映 主题 帮助 │
├────────┬──────────────────────────────────────────────────┬─────────────────────────┤
│ 左栏    │                                                  │ 右栏                     │
│ 幻灯片  │                 画布（1920×1080）                │ 元素 / 页面属性           │
│ 缩略图  │                                                  │ 图层                     │
├────────┴──────────────────────────────────────────────────┴─────────────────────────┤
│ 底栏：页码 · 画布尺寸 · 当前选中 ────────────────── −   100%   ＋                   │
└───────────────────────────────────────────────────────────────────────────────────────┘
```

常用功能在**上方**（插入、格式刷、查找、随选区出现的文字格式条），
低频微调（缩放）在**下方**，右侧只保留「改属性」与图层。
两侧面板都可收起，收起后由贴在卡片边缘、上下居中的拉手恢复，不会再「关掉就打不开」。
