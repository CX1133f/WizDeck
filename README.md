# WizDeck · 把 HTML 课件变成可编辑的 PPTX

[English](./README.en.md) · **简体中文**

> 单文件 · 纯离线 · 零运行时依赖 · 无需服务器

```
双击打开 WizDeck.html  →  拖入 HTML  →  编辑  →  导出 PPTX
```

WizDeck 把一个 HTML 文档解析成幻灯片，在可视化工作台里直接改版式与文字，
再导出成**真正可编辑的 `.pptx`** —— 文字是真文本框，不是图片。

交付物就是仓库根目录的 **`WizDeck.html`**（约 810 KB），双击即用，不联网、不装依赖。

---

## 它解决什么问题

老师手上的课件通常是一份 AI 生成的 1920×1080 HTML。这份 HTML 好看，但**改不动**：
改一个字要翻源码，挪一个卡片要对像素，最后还得想办法变成 PPT。

WizDeck 补上中间那一段：

| 环节 | 做的事 |
| --- | --- |
| **解析** | 自动识别分页结构，把每一页还原成 1920×1080 的独立画布，版式 1:1 保留 |
| **编辑** | 拖动、缩放、旋转、双击改字、改色、改字号、对齐分布、图层、撤销重做 |
| **导出** | 浏览器内直接生成 PPTX（OOXML + ZIP 全部自己实现），文字是真文本框 |

## 快速开始

**用起来**

1. 双击 `WizDeck.html`（Chrome / Edge / Firefox 均可，不需要服务器、不联网）。
2. 点空状态的「打开 HTML 文件」，或把 `.html` 直接拖进窗口（之后随时 `Ctrl+O` 换文件）。
3. 左栏切页 / 拖拽排序；画布上点选元素；右栏改属性；双击文字直接改。
4. 点右上角「**保存与导出 ▼**」→ 选「导出 PPTX」，浏览器下载 `.pptx`。

仓库里带了两个可直接试的文件：`samples/sample-fractions.html`（6 页示例课件，
配套已校验的导出产物 `samples/output/sample-fractions.pptx`）和 `samples/cw_33.html`。

**改源码后重新出单文件**

```bash
node build.mjs      # 把 build/ 下的 8 个 JS + shell.html + styles.css 组装进一个 HTML
```

`build.mjs` 会顺带做**自包含校验**（不允许有外部脚本 / 样式 / 字体引用）——
单文件离线是硬约束，构建阶段就该拦住。

## 核心能力

### 元素库

顶栏插入组，每一项都是「左边图标 + 右边文字」的下拉：

| 分组 | 内容 |
| --- | --- |
| **文本框** | 横向 · 竖向 |
| **标题** | 一级 · 二级 · 三级 · 四级 |
| **形状** | 矩形 · 圆角矩形 · 圆形 · 椭圆 · 三角形 · 平行四边形 · **多边形** · 直线 · 箭头 · 双向箭头 · **曲线 · 连接线 · 曲线连接线 · 自由绘制** |
| **表格** | 弹窗自定义行列；插入后右栏可继续增删行列；**双击任意单元格改字**（表头、数据行都行） |
| **公式** | 插入公式 · 插入 LaTeX（弹窗输入 + 实时预览） |
| **图表** | 柱状图 · 折线图 · 饼状图；选中后**右栏「图表数据」段**直接改标题 / 分类 / 系列数值，停手 0.4 秒自动重画（双击图表会把那段唤到眼前） |
| 图片 · 视频 | 直接调用系统文件选择器 |

形状带**约束**：圆形锁宽高比（怎么拖都是正圆），椭圆自由拉伸；直线 / 箭头 / 双向箭头锁死杆高、只留两端可拖；曲线 / 曲线连接线留最小高度（太扁就看不出弧度）；
**自由绘制 / 多边形**等比缩放（笔迹按原始包围盒存比例点，拉伸不会把线条压扁）—— 无意义的手柄会直接隐藏，不给你点「没反应」的按钮。

**曲线 / 曲线连接线**是**三次贝塞尔**：两个端点定大小与位置，两端各挂一条**切线手柄**（选中后以方形小柄显示、附虚线辐条）—— 拖切线手柄只改该端的弯曲方向与程度、不把图形撑大，拖端点才改尺寸。旧的「单拐点」曲线一打开就自动升级成这一套（拐点等价换算成两条切线），老工程照常能改。

**多边形 / 自由绘制**在画布上手绘：自由绘制按住拖一笔即成；多边形逐点单击定顶点，双击 / 回车 / 点回起点（靠近起点会自动高亮吸附）即闭合，`Esc` 退出，绘制中有虚线橡皮筋与逐点描边动画。多边形**画完一个就自动退出工具**，要再画得重新点菜单 —— 免得你以为停手了却连着戳出第二个。画完的图形**选中即可继续编辑**：多边形每个顶点都是可拖手柄、逐点拖动即时重算包围盒，曲线拖端点与切线，**多边形还能填色**（右栏「填充」选底色，描边颜色与粗细各自独立可调），自由绘制则按描边处理。

### 第二行：跟着选区走的操作栏

顶栏第一行只放**固定功能**（新建 / 插入 / 查找 / 保存导出 / 主题帮助），不随选区跳变。
紧挨着它下面是一条**上下文操作栏**，选中什么就换什么：

| 当前状态 | 第二行显示 |
| --- | --- |
| 没选中任何元素 | `幻灯片` —— 版式、背景 |
| 选中元素 | `元素` —— 对齐 8 键 · X/Y/宽/高/旋转 · 填充 · 上移下移置顶置底 · 复制删除 |
| 选中表格 | 追加 `＋行 －行 ＋列 －列` |
| 选中有文字的元素 | 追加 `B I U · A− 字号 A+ · 文字对齐 · 文字色` |
| 还没载入文档 | 整条隐藏，不留空行占画布 |

右栏因此只留**长尾**：图层列表、演讲备注、圆角 / 边框 / 字体 / 字重 / 行高 / 字距 / 透明度、
色板、组合解组、自定义 CSS。

**同一个控件只存在于一处** —— 文字色、字号、文字对齐、置顶置底原本各有两份，
这一轮各自并成了第二行里的那一份。两份控件就意味着两套状态，
改一个忘了改另一个，比不做还糟。

### 按钮手感

「不流畅」常常不是性能问题，而是**过渡时长不统一**：审计脚本把全应用每个可见按钮量一遍，
曾经量出 7 种时长（0.1 / 0.12 / 0.13 / 0.14 / 0.15 / 0.16 / 0.18）散在各处，
界面上不同部位应答快慢不一样 —— 用户说不出哪儿不对，但确实「不跟手」。
现在统一到 `--dur: .14s` 一个 token，118 个可见按钮的时长收敛成**一种**。

三条硬指标都在回归里盯着，改坏了会红：

| 指标 | 标准 |
| --- | --- |
| 命中区 | ≥ 24×24（贴边拉手 20×52 是竖条，有意例外） |
| 光标 | 全部 `pointer` / `not-allowed` |
| 悬停解释 | 纯图标按钮必须带 `title` |
| 过渡时长 | 全应用**只有一种** |

### 编辑

- 拖动 / 缩放 / 旋转（`Shift` 吸附 15°），手柄在任何缩放级别都保持恒定屏幕尺寸
- 双击改字：光标落在哪个词上就编辑哪个词，`Esc` 退出
- 对齐与分布、图层（点选 / 拖拽重排 / 锁定 / 隐藏）、吸附参考线（`Alt` 临时关闭）
- 撤销 / 重做、查找（`Ctrl+F`）、格式刷、自动保存（另存为单文件工程）

### 导出与放映

- **导出 PPTX**：文本、纯色块、图片是真对象；渐变 / 阴影 / 旋转 / SVG 等复杂效果烘成 PNG 贴图
- **放映模式**（`F5`）：保留原始 HTML 的动效；**整页按视口等比缩放并居中**，
  任何分辨率下都不会裁掉画面（备注面板展开时画布自动上移让位）
- **深色主题**、缩略图实时预览

## 导出的 PPTX 里，什么是「可编辑」的

分层策略按「**正确性优先，可编辑性其次**」决定：

| 画面内容 | 导出成 | 可否在 PPT 里继续编辑 |
| --- | --- | --- |
| 文字 | 真文本框（**逐视觉行**定位，断行与浏览器一致） | ✅ 改字、字号、颜色、字体 |
| 纯色块 / 边框 / 圆角矩形 | 真形状（`p:sp`） | ✅ 改填充、轮廓、圆角 |
| 图片（data URI） | 真图片对象（`p:pic`） | ✅ 替换图片 |
| 渐变 / 外阴影 / 滤镜 / 旋转 / SVG / 半透明 | 浏览器渲染后作为 PNG 贴图 | ⚠️ 视觉 100% 一致，但这一层不可再改文字 |
| 被贴图元素压住的文字 | 一起烘进贴图 | ⚠️ 同上（优先保证不遮挡） |
| 页面底色 | 铺满画布的矩形形状 | ✅ 直接改背景色 |
| 演讲备注 | 写入 PPTX 备注页 | ✅ |

一个 6 页示例的实测结果：**167 个形状，其中 97 个是可编辑文本框**。

导出器在打包前会做两层自检，任一不通过都会写进 `warnings` 并在控制台报错：
① 每个 XML 部件的良构性 + 主要标签配平；② ZIP 字节流回读比对（压缩大小 / 原始大小 / CRC）。

## 分页识别规则

引擎按下面的顺序判定怎么切页，命中即停：

1. `data-wd-slide` 显式标记 —— 最高优先级
2. reveal.js / impress.js 约定（`.slides` / `.step` / `.impress` / `data-reveal`）
3. 语义与类名提示（`<section>`、`.slide`、`.page` …）**并用几何一致性打分**
   （宽度高度是否一致、长宽比是否接近 16:9、每页是否够大）
4. 全幅绝对定位区块（AI 生成课件的常见写法）
5. 统一几何检定的任意候选集合
6. 唯一外层容器 → 往里再找一层
7. 兜底：整篇当 1 页（界面会提示置信度低）

想让分页 100% 确定，用第一种：

```html
<section class="slide"> … </section>
<!-- 或 -->
<div data-wd-slide> … </div>
<!-- 或 -->
<div class="slides"><section>…</section><section>…</section></div>
```

写 HTML 时的建议：**页面 1920×1080、用绝对定位、用系统字体**，还原度最高。

## 已知限制

- **跨域素材**（图片 / 字体）读不到内容会被跳过；本地文件与 `data:` URI 不受影响。
- **自定义 `@font-face` 不嵌入 PPTX**。文字保真取决于演示电脑上是否装有对应字体；
  引擎已为中文单独声明 `eastAsia` 字体以降低回退风险。
- **动画与交互**不会进入 PPTX（静态导出）；放映模式可以放原始 HTML 动效。
- **表格不是 PowerPoint 原生表格对象。** 每个单元格导出成一个真文本框（可改字），
  外加一个表格底框，PPTX 里**没有** `a:tbl`。实测一份 4×5 的表 = 25 个单元格文本框。
- **公式导出成普通文本运行，不是 OMML 公式对象。** 能改字，但上下标、分式、根号在
  PowerPoint 里不再「是公式」。另外画布内的公式依赖浏览器的 **MathML Core**
  （Chrome 109+ / Edge / Firefox），更老的 Chromium 会退化成源文本 —— 单文件离线装不下 KaTeX。
- **图表按 PNG 贴图导出**（`p:pic`）。画布**内**是完整可编辑的（右栏改数据、自动重画），
  但导出的 PPTX 里它是一张图，在 PowerPoint 里点不开数据表。
- **三角形 / 平行四边形 / 直线 / 箭头 / 双向箭头 / 曲线 / 连接线 / 曲线连接线 / 多边形 / 自由绘制也走贴图**
  （依赖 `clip-path` 或内嵌 SVG，没有对应的 `prstGeom` 预设），视觉 100% 一致但导出后不可再编辑。
- **源页面不会被归一化尺寸。** 1280×720 这类页面会等比缩放居中留白，绝不拉伸 ——
  保留版式优先于铺满画布。
- **视频只保留封面**，不进入工程文件也不进入 PPTX（单文件装不下几十 MB，
  且 `blob:` 地址重新打开工程时必然失效）。极短（不足 0.12 秒）或还在直播的流
  没有可 seek 的区间，封面只能取第 0 帧。
