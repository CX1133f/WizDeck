# WizDeck · Turn HTML decks into editable PPTX

**English** · [简体中文](./README.md)

> Single file · Fully offline · Zero runtime dependencies · No server needed

```
Open WizDeck.html  →  Drop in HTML  →  Edit  →  Export PPTX
```

WizDeck parses an HTML document into slides, lets you fix layout and wording in a visual
workbench, then exports a **genuinely editable `.pptx`** — text becomes real text boxes,
not images.

The deliverable is **`WizDeck.html`** in the repository root (about 634 KB). Double-click it
and you're running: no network, no install.

---

## What problem it solves

A teacher's deck is usually a 1920×1080 HTML file generated by AI. It looks good but
**can't be edited**: changing one word means digging through source, moving one card means
nudging pixels, and somewhere along the way you still have to turn it into a PPT.

WizDeck fills in the middle:

| Stage | What it does |
| --- | --- |
| **Parse** | Detects the pagination structure, restores each page as an independent 1920×1080 canvas, preserving the layout 1:1 |
| **Edit** | Drag, resize, rotate, double-click to edit text, recolor, change font size, align & distribute, layers, undo/redo |
| **Export** | Generates the PPTX right in the browser (OOXML + ZIP implemented from scratch); text becomes **real text boxes** |

## Quick start

**Using it**

1. Double-click `WizDeck.html` (Chrome / Edge / Firefox; no server, no network).
2. Click "Open HTML file" in the empty state, or drag an `.html` file straight into the
   window (`Ctrl+O` swaps files later).
3. Switch and reorder slides in the left rail; click elements on the canvas; edit
   properties in the right panel; double-click text to edit it.
4. Click "**Save & Export ▼**" → "Export PPTX"; the browser downloads the `.pptx`.

Two files ship with the repo for a quick trial: `samples/sample-fractions.html`
(a 6-page sample deck, with a validated export at `samples/output/sample-fractions.pptx`)
and `samples/cw_33.html`.

**Rebuilding the single file after a source change**

```bash
node build.mjs      # assembles the 7 JS files + shell.html + styles.css into one HTML
```

`build.mjs` also runs a **self-containment check** (no external script / style / font
references allowed) — being a self-contained offline file is a hard constraint, so the build
step is where it should be caught.

## Capabilities

### Element library

Everything in the top-bar insert group is a "icon on the left, label on the right" dropdown:

| Group | Contents |
| --- | --- |
| **Text box** | Horizontal · Vertical |
| **Title** | Level 1 · Level 2 · Level 3 · Level 4 |
| **Shape** | Rectangle · Rounded rectangle · Circle · Ellipse · Triangle · Parallelogram · Line · Arrow · Double arrow |
| **Table** | Dialog for rows/columns; can keep adding/removing rows and columns in the right panel afterwards; **double-click any cell to edit** (header and data rows alike) |
| **Formula** | Insert formula · Insert LaTeX (dialog with live preview) |
| **Chart** | Bar · Line · Pie; **double-click opens a data sheet** to edit title / categories / series values, redrawn immediately |
| Image · Video | Straight to the system file picker |

Shapes carry **constraints**: a circle locks its aspect ratio (always stays round), an ellipse
stretches freely, and lines / arrows / double arrows lock their height (6 / 26 / 26px) —
handles that would be meaningless are hidden outright, rather than offering buttons that do
nothing.

### Second row: a contextual bar that follows the selection

The first row of the top bar carries **fixed functions only** (new / insert / find / save /
theme / help) and never jumps around. Right below it sits a **contextual bar** that swaps its
contents with the selection:

| Current state | What the second row shows |
| --- | --- |
| Nothing selected | `Slide` — layout, background |
| An element is selected | `Element` — 8 align keys · X/Y/W/H/rotation · fill · up/down/front/back · duplicate/delete |
| A table is selected | Adds `＋row −row ＋col −col` |
| An element with text is selected | Adds `B I U · A− size A+ · text alignment · text colour` |
| No document loaded | The whole bar hides — no empty row eating the canvas |

The right panel therefore keeps only the **long tail**: the layer list, speaker notes, corner
radius / border / font / weight / line height / letter spacing / opacity, swatches, group and
ungroup, and custom CSS.

**Each control exists in exactly one place** — text colour, font size, text alignment and
front/back each used to exist twice; this round merged each pair into the second-row copy.
Two copies of a control means two sources of state, and forgetting to update one is worse than
not moving anything at all.

### Button feel

"Irresponsive" is often not a performance problem — it is **inconsistent transition durations**.
An audit script measures every visible button in the app; it once found **7 different
durations** (0.1 / 0.12 / 0.13 / 0.14 / 0.15 / 0.16 / 0.18) scattered around the stylesheet.
Different parts of the interface then answer at different speeds — users can't say what's
wrong, it just doesn't feel responsive. Everything now goes through one `--dur: .14s` token,
and the 118 visible buttons converge to **a single duration**.

Three hard metrics are guarded by the regression suite, so a regression turns them red:

| Metric | Rule |
| --- | --- |
| Hit target | ≥ 24×24 (the 20×52 edge tab is a deliberate exception) |
| Cursor | always `pointer` / `not-allowed` |
| Hover hint | icon-only buttons must carry a `title` |
| Transition duration | exactly **one** value app-wide |

### Editing

- Drag / resize / rotate (`Shift` snaps to 15°); handles keep a constant on-screen size at
  every zoom level
- Double-click to edit: the caret lands on the word you clicked, `Esc` exits
- Align & distribute, layers (click to select / drag to reorder / lock / hide), snap guides
  (`Alt` suspends snapping temporarily)
- Undo / redo, find (`Ctrl+F`), format painter, auto-save (as a single-file project)

### Export & presenting

- **Export PPTX**: text, flat color blocks and images become real objects; gradients,
  shadows, rotations, SVG and other effects are baked into PNG images
- **Presentation mode** (`F5`): keeps the original HTML animations; the page is scaled
  proportionally to the viewport and centred, so no part of the slide is ever cut off at
  any resolution (the canvas also moves up to make room when speaker notes are shown)
- **Dark theme**, live slide thumbnails

## What stays editable in the exported PPTX

The layering strategy is decided by **correctness first, editability second**:

| On screen | Exported as | Still editable in PowerPoint? |
| --- | --- | --- |
| Text | Real text boxes (positioned **per visual line**, so line breaks match the browser) | ✅ text, size, color, font |
| Flat color blocks / borders / rounded rectangles | Real shapes (`p:sp`) | ✅ fill, outline, corner radius |
| Images (data URI) | Real picture objects (`p:pic`) | ✅ replace the image |
| Gradients / drop shadows / filters / rotation / SVG / translucency | Browser-rendered, baked as a PNG image | ⚠️ pixel-identical, but text in this layer is no longer editable |
| Text covered by a baked layer | Baked into the same image | ⚠️ same as above (not overlapping text matters more) |
| Page background | A rectangle shape filling the canvas | ✅ change the background color directly |
| Speaker notes | Written to the PPTX notes page | ✅ |

Measured on a 6-page sample: **167 shapes, of which 97 are editable text boxes**.

Before packing, the exporter runs two self-checks; if either fails, the problem goes into
`warnings` and is logged to the console:
① well-formedness of every XML part plus tag balancing; ② ZIP byte-stream read-back
comparison (compressed size / raw size / CRC).

## Slide-splitting rules

The engine tries these in order and stops at the first hit:

1. Explicit `data-wd-slide` markers — highest priority
2. reveal.js / impress.js conventions (`.slides` / `.step` / `.impress` / `data-reveal`)
3. Semantic and class-name hints (`<section>`, `.slide`, `.page` …) **scored by geometric
   consistency** (do widths and heights match, is the aspect ratio near 16:9, is each page
   big enough)
4. Full-bleed absolutely positioned blocks (the common shape of AI-generated decks)
5. Any candidate set that passes the uniform-geometry check
6. A single outer container → look one level deeper
7. Fallback: treat the whole document as 1 page (the UI shows a low-confidence notice)

For 100% deterministic splitting, use the first option:

```html
<section class="slide"> … </section>
<!-- or -->
<div data-wd-slide> … </div>
<!-- or -->
<div class="slides"><section>…</section><section>…</section></div>
```

Recommendation for authoring: **1920×1080 pages, absolute positioning, system fonts** —
that combination reproduces most faithfully.

## Known limitations

- **Cross-origin assets** (images / fonts) that cannot be read are skipped; local files and
  `data:` URIs are unaffected.
- **Custom `@font-face` is not embedded in the PPTX.** Text fidelity depends on whether the
  presenting machine has the font installed; the engine declares a separate `eastAsia` font
  for Chinese to reduce fallback risk.
- **Animation and interaction do not survive export** (static export only); presentation mode
  plays the original HTML animations.
- **Tables are not native PowerPoint table objects.** Each cell exports as a real text box
  (text is editable) plus a backing rectangle, so the PPTX contains **no** `a:tbl`.
  Measured: a 4×5 table becomes 25 cell text boxes.
- **Formulas export as plain text runs, not OMML equation objects.** They are editable as
  text, but superscripts, fractions and radicals stop being "equations" in PowerPoint.
  On canvas, formulas rely on the browser's **MathML Core** (Chrome 109+ / Edge / Firefox);
  older Chromium degrades to showing the source text — a single offline file cannot bundle
  KaTeX.
- **Charts export as PNG images** (`p:pic`). Inside the workbench they are fully editable
  (double-click to change data, redrawn instantly), but in the exported PPTX they are images
  and the data sheet cannot be opened.
- **Triangles, parallelograms, lines, arrows and double arrows also export as images**
  (they rely on `clip-path` or inline SVG and have no matching `prstGeom` preset) —
  pixel-identical, but not editable afterwards.
- **Source pages are not normalized in size.** A 1280×720 page is scaled proportionally and
  centered with letterboxing — never stretched. Preserving layout beats filling the canvas.
- **Video keeps only its poster frame**, and neither the project file nor the PPTX embeds the
  video itself (a single file cannot hold tens of megabytes, and `blob:` URLs inevitably die
  when the project is reopened). Streams shorter than 0.12 s, or still live, have no seekable
  range, so the poster can only come from frame 0.
